The handoff between a planner agent and a builder agent, drawn.

Install relay

relay automates the plan/report handoff between two AI coding agent panes running under herdr. You talk to the planner; the planner hands work to a builder; relay moves the files between them. That copy-paste is the only manual step in the loop, and it is pure mechanism.

herdr is a hard dependency, not an integration. herdr 0.8.2 or newer must be on your PATH. herdr owns the panes, and everything relay observes or controls goes through the herdr CLI. Without it, relay does nothing.

The outbound leg runs while the planner is mid-turn, so the planner just calls relay send and waits for it to return. The inbound leg happens after the planner’s turn has ended, when no model is running to notice that a builder finished. Something has to be awake then. That is the only reason a daemon exists.

The round

Six verbs, run from inside the planner’s herdr pane, in the repository you want worked on.

relay bind --builder claude/anthropic/sonnet   # open a builder tab, bind it to this tree
relay send --file plan.md                      # hand it the plan
relay status                                   # watch the round
relay wait                                     # block until it closes or needs you
relay pull                                     # print the pending notice, with the report's path
relay done <name>                              # stop relaying when you are satisfied

relay bind reads the planner’s pane from $HERDR_PANE_ID, which herdr sets inside every pane it manages, so it has to be run from inside one. The builder writes NNN-report.md when it has finished and then creates an empty NNN-done as its last action; relay closes the round on that marker. A builder that goes idle without the marker is nudged once, then its report is delivered flagged unmarked; if it wrote no report, its terminal is scraped instead and flagged scraped.

relay wait exits with meaning, so a shell can branch on it: 0 closed on the marker, 2 closed without it, 3 needs you, 4 done or unbound, 124 timed out. relay pull prints the pending notice, with the report’s path, to stdout instead of typing it anywhere, which is the safe way for the planner to fetch one mid-turn.

What a round leaves on disk

Under ~/.local/state/relay/<name>/. State resolves through $XDG_STATE_HOME; config through $XDG_CONFIG_HOME, else ~/.config.

bind.json
The binding itself.
log.jsonl
The append-only round log. relay log <name> formats it.
NNN-plan.md
Planner to builder.
NNN-report.md
Builder to planner.
NNN-question.md
A blocked builder’s dialog, captured.
NNN-diff.patch
The round’s captured patch. relay diff --stat, or --drift for what changed between rounds.
NNN-done
Empty. Its existence is the completion contract.

relay unbind --archive packs a binding into .archive/ as a gzipped tarball instead of deleting it. Without the flag, unbind deletes; relay gc is the verb that archives by default.

Builders

A pane, by default. Every agent relay spawns opens in its own herdr tab in the planner’s workspace, labelled with the agent’s name, without moving focus. There is no split option: side-by-side panes stop being readable at two or three builders, and tabs scale.

Or headless. relay bind --headless makes the builder a process instead of a pane, and nothing opens at bind. Each relay send starts the harness’s non-interactive form — agy -p …, claude -p …, opencode run … — in the binding’s tree, writes the streamed JSON events to NNN-builder.jsonl, and returns. The daemon renders that stream into NNN-builder.log as it grows, about two seconds behind, so relay ui, relay status and tail -f all show the round live.

One fresh process per round is the whole trade: no tab, no idle harness holding memory — an idle opencode builder is roughly 800 MB — and no dialogs, because stdin is closed and relay answer is refused. Also no memory across rounds, so a headless plan has to carry its own context.

Several at once. relay add attaches another builder to the same planner on its own git worktree, so they never contend for files; exactly one agent may write to a working tree. relay fork branches a new binding from an earlier round, copying that round’s history and artifacts and launching a fresh builder in a dedicated worktree.

relay bind --builder claude/anthropic/sonnet --name api
relay add  --name frontend --builder claude/anthropic/sonnet
relay add  --name backend  --builder opencode/openrouter/z-ai/glm-5.3-flash

relay send --name frontend --file ui_plan.md
relay send --name backend  --file api_plan.md

The daemon

relay daemon is the reconciler — one per herdr session, run from any spare terminal or installed as a systemd user unit or a LaunchAgent with make service. It polls herdr and does three things: deliver a finished builder’s report to the planner, capture the dialog when a builder blocks, and keep round accounting. Nothing else needs it running; without it, no finished report is queued, so relay pull has nothing to print. Only one runs at a time — it takes an exclusive lock on $XDG_STATE_HOME/relay/.daemon.lock and refuses to start beside another.

What relay status shows

ACTIVE
Someone is working. Nothing needs a human yet.
NEEDS YOU
relay has stopped and a person must act: a blocked builder, a dead builder pane or a lost planner pane (flagged and reported, never cleaned up), a round past its timeout, a binding at its round cap.
HELD
A payload is ready, but the planner pane is focused. The row carries the hold’s clock.
DONE
You declared the work verified. Relaying stopped deliberately, not because anything went wrong.

Mid-round switching

The daemon can replace a builder while a round is open — when its pane has been gone for 30 seconds, or when you gate its provider. It resolves builder again through policy.json and the ledger, starts the pick in the same tree, and hands it the same round’s plan. The round number does not change; the round clock restarts. A switch entry in the log says what was tried and why. Bounded by max_switches, default 2; 0 turns switching off. After that the binding goes NEEDS YOU; the count resets only when the round advances. A switch that finds every candidate gated goes NEEDS YOU too, and that one recovers on its own once relay available clears a provider.

Lifecycle hooks

The daemon runs any executable in ~/.config/relay/hooks/state_changed.d/ and ~/.config/relay/hooks/round_started.d/, detached, with a 10-second timeout, and RELAY_EVENT, RELAY_BINDING, RELAY_STATE, RELAY_OLD_STATE and RELAY_ROUND in the environment. Output and failures go to ~/.local/state/relay/hooks.log. A missing directory is a silent no-op.

Candidates, policy, availability

A candidate is one way to fill a role, named by the token harness/provider/model. relay ships none: which model you are entitled to run is a fact about your accounts, not about relay. You write ~/.config/relay/candidates.json, where harness is a kind relay knows — agy, claude, opencode — and roles names which of builder, reviewer and researcher the candidate serves.

~/.config/relay/policy.json sets the order to try them in, per role. relay policy prints what relay would pick right now, computed by the same code bind runs, so it cannot disagree with what bind does next. There is no relay policy set — edit the file.

relay unavailable claude/anthropic/sonnet --for 2h
relay available anthropic

A limit gates the provider — every candidate with that provider — because that is who enforces the quota, not the model. Without --for it stays gated until you clear it, because relay does not know your provider’s reset schedule. relay records spawn failures itself, gating that one candidate for ten minutes, and those expire on their own. Name a gated candidate explicitly and relay prints a note and proceeds: you named it.

What relay refuses to do

relay makes no judgements. It moves files, types prompts, and watches herdr’s live agent state. Whether a report is good, whether a question needs a human, whether the work is done — every one of those decisions stays with the planner, or with you. Three structural refusals follow from that.

File handoffs, not screen scraping

Agent TUIs run on the alternate screen, and completed responses scroll out of reach of a terminal read regardless of how many lines you ask for. herdr’s own prescribed workaround is to have the agent write its response to a file and reply with the path, so relay hands work over as files on disk. Nothing depends on reading a terminal correctly.

Panes are yours

relay opens a pane only for an agent it starts (a builder, its mid-round replacement, a consult) and closes a pane in exactly two places. done and unbind leave a pane builder running. A BROKEN, ORPHANED or timed-out binding is flagged and reported, never cleaned up: that terminal is often the only record of why a round went wrong, and throwing it away automatically is worse than leaving a process up. Closing panes you have finished with stays your job.

The anti-clobber rule

herdr agent prompt types text into a pane and presses Enter, and relay cannot see what you have half-typed. So a focused planner pane is treated as unsafe to inject into: relay holds the payload and sends one notification instead of typing over you. A held payload leaves the hold three ways — your focus moves to another pane, the planner’s input box is seen empty, or the visible screen has not changed for --held-grace (60 s), in which case an abandoned draft gets the payload appended, accepted on purpose. relay pull bypasses all of it by printing to stdout.

Also in the box

relay ui
A full-screen reader for live bindings: report, terminal, diff and log tabs. Strictly read-only — it never mutates state, types into panes, or appends to a log.
relay diff [--stat] [--drift]
The round’s captured patch, its diffstat, or the drift between rounds. Captured only when git is on PATH.
relay ask --role reviewer
A one-shot consult beside a binding. Not persistent, does not advance the round, does not count against the one-writer-per-tree rule. Its findings land as a file and are queued to the planner like any other report.
relay answer --pick
Answer a builder blocked at a dialog, via send-keys. relay re-checks that herdr still reports it blocked, and refuses to guess which builder you meant.
relay doctor
Preflights herdr, the daemon, each harness binary, herdr integrations and the role files, and prints the literal fix command for a missing daemon, integration or role file.
relay statusline
One row per live binding of this planner pane, under the Claude Code prompt: ○ name rN · builder · what relay is waiting on … age · STATE, with ● on a NEEDS YOU row.
relay gc [--dry-run]
Clear every binding you marked DONE, in one pass. Archives by default.
relay agent print --kind
One of the role definitions relay ships, for one harness kind: plan-executor by default, or with --role the read-only researcher, reviewer, or architect — the planner persona relay ships but never launches.

Install

As a herdr plugin, if you already run herdr 0.8.2 or newer:

herdr plugin install fuad-daoud/relay

That downloads the release binary matching the plugin manifest and verifies its checksum. You get a relay ui overlay pane, three popup pickers — pick-done, pick-unbind, pick-answer — an install-service action that installs the binary to ~/.local/bin/relay and registers the daemon with systemd or launchd, and a startup check that tells you if the reconciler is not running. herdr does not sandbox plugins: the scripts are scripts/plugin-*.sh in the repository, and they are worth reading before you install.

As a release binary. Prebuilt binaries for Linux and macOS, amd64 and arm64, are attached to every release. Unpack one and put relay on your PATH.

From source, with a Go toolchain:

go install github.com/fuad-daoud/relay/cmd/relay@latest

Then run relay doctor and work through what it prints.

Requirements

herdr ≥ 0.8.2
On PATH. A hard runtime dependency: herdr owns the panes, and everything relay observes or controls goes through its CLI.
Two harnesses
One for the planner, one for the builder. relay knows how to start agy, claude and opencode.
git
Optional. Without it relay works normally, but rounds capture no diffs.
Linux or macOS
Both are exercised in CI. Windows is not supported — the blocker is herdr, not relay. The tree still cross-compiles for windows/amd64 and refuses at runtime with a clear error rather than running without a state lock.
Go 1.22+
To build from source. Not needed for a release binary.
