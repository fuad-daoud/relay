## 1. What the README must say (the facts to verify in the code first)

1. **Storage.**
   - Everything lives in `$XDG_STATE_HOME/relevo/relevo.db` (0600): config sections, secrets,
     bindings, logs, gates, planners, sealed round files and archives.
   - Also in the state root:
     - `.daemon.lock`, and the per-root `.lock`;
     - `.worktrees/`;
     - binding dirs holding only the files of **unsealed** rounds;
     - on a server, `serve/repos/`, `serve/tmp/` and `serve/bindings/<owner>/` (dirs only).
   - `~/.config/relevo` is not used. A config file dropped there is imported on the next command
     and removed.
2. **Config.** `relevo config` with its forms (the P2b table). The sections are candidates,
   policy, roles, prices, servers and hooks. Secrets are set with `relevo config secret set`.
   Hooks are argv lists: `relevo config set hooks.<event> '[["/path/script","arg"]]'`.
3. **The command set.** Take it from `relevo help` in the code (the usage const in
   `cmd/relevo/main.go`). Every removed verb's replacement comes from `removedVerbs`.
4. **The planner loop:**
   - `relevo bind [--worktree]`;
   - `relevo send`;
   - `relevo wait` prints the report;
   - `relevo show --report|--diff|--drift|--log|--gate|--findings`;
   - `relevo gate` for usage limits;
   - `relevo done`, and `relevo unbind [--done]`.
5. **History and archives.**
   - `relevo history`, `--tab`, `--stats`;
   - archiving keeps the binding's rows in the DB;
   - `unbind --done` archives every DONE binding;
   - old tarballs are imported once.
6. **The server.**
   - `relevo serve [--state DIR]` uses the machine DB.
   - Clients (`serve enroll/clients`) and TLS (`serve init`) are stored in the DB.
   - The admin verbs find a running daemon's `--state` through the DB.
   - A DONE served binding is cleaned up once its rounds are acked, or after 7 days: its worktree,
     its branch and `refs/relevo/<name>/*` in the bare repo are removed, and the record is archived.
     **This one lands in a parallel round** (`/home/fuad/projects/relevo/docs/plans/2026-09-24-p5-r2-cleanup.md`), so it is not
     in this tree. Document it from that plan, and do not stop because the code lacks it.
7. **Status line:** `relevo status --line` in Claude Code's `statusLine` setting.
