## 1. System overview

`relay diff [--round N]` prints the captured unified patch raw
(`cmd/relay/main.go` `cmdDiff` -> `relay.ReadDiff`, `capture.go:320`). A
review is the planner reading it and re-typing findings into the next plan
by hand, losing the anchor. After this round: `relay diff --anchors`
prefixes each hunk with its post-image location and each added/context
line with a `path:line ` gutter; a comments file is one `path:line: text`
per line (a line without an anchor is a general comment); `relay review
<name> --file comments.md [--round N] [--out path] [--send]` validates
every anchor against the round's patch (post-image), renders a plan with
one task per comment quoting the anchored hunk (+/-3 lines) and the
comment verbatim, writes it (default `<binding dir>/NNN-review-plan.md`,
NNN = the reviewed round) and prints the path; `--send` hands it to `Send`
as the next round. Design question 1: the rendered plan says "Fix ONLY what
these comments ask" (the planner deletes it if the round is broader).
Question 2 (ui) is not now. There is no diff library in `go.mod`; a small
unified-diff reader is written here (`internal/patch`), sized for relay's
own captured patches.

## 6. Error handling

- Unknown anchor -> refused before any write, every bad line listed.
- `--send` failure after the plan was written: the plan path is still
  printed; the send error is returned (exit 1).
- A patch `Annotate` cannot parse -> `relay diff --anchors` prints the
  parse error and exits 1; plain `relay diff` is unchanged.
