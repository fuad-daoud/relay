## 1. System overview

relay already emits lifecycle events through `internal/hooks`
(`state_changed`, `round_started`, `fork_created`, `builder_stalled`,
`binding_stale`; `LocalDispatcher.Dispatch` runs every executable under
`~/.config/relay/hooks/<event>.d/`). Getting a Slack or Discord message
when a three-hour builder hits NEEDS YOU means writing a curl script per
machine. This round adds a **webhook sink** beside the scripts: `policy.json`
`notify.webhooks` lists URLs with an event filter and an optional
`format` (`json` -- the event as JSON; `slack` -- `{"text": ...}`;
`discord` -- `{"content": ...}`); the dispatcher POSTs each matching event
in a detached goroutine with a short timeout, never blocking a tick, and
logs failures to `hooks.log`. The `state_changed` filter accepts a state
suffix so `state_changed:needs_you` is the one most people want. No
retries, no queue: a webhook is best-effort like a hook script.

## 3. Data structures

```
// internal/policy
type Webhook struct {
    URL    string   `json:"url"`               // https:// or http://; required
    Events []string `json:"events,omitempty"`  // event names; "" list = every event. "state_changed:<state>" matches state_changed with Event.State == <state> (e.g. needs_you, done)
    Format string   `json:"format,omitempty"`  // "json" (default) | "slack" | "discord"
}
type NotifyPolicy struct { Webhooks []Webhook `json:"webhooks,omitempty"` }
Policy.Notify *NotifyPolicy `json:"notify,omitempty"`
// validation: URL parses with scheme http/https; Format in {"", json, slack, discord}; every Events entry is a known event name, optionally with ":<state>" only for state_changed -> ErrBadPolicy naming the entry
```

## 6. Error handling

- Policy validation errors name the offending webhook index and field.
- Posting never blocks or fails the caller; every failure is one log line.
- A webhook URL that resolves to nothing: the 5 s timeout ends it.
