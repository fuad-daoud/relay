## 1. System overview

After a green round the planner types the same sequence by hand: rebase
onto main, `make check`, push, `gh pr create`. `relay land` makes that one
verb with a log line. It never merges, never deletes a branch or worktree,
is never triggered by the marker. Order, stopping at the first failure with
nothing pushed: preconditions (worktree binding, no open round unless
`--force`, clean tree) -> fetch + rebase onto the base ref (conflict ->
abort, list paths, exit 3) -> the binding's gate on the rebased tree
(`land-gate.log`, fail -> exit 2) -> push (`--force-with-lease` when
the branch already exists on the remote, since a rebase rewrites it) ->
PR (`--pr` runs `gh pr create --head <branch> --base <base> --fill` when
`gh` is on PATH; otherwise, or without `--pr`, the exact command is printed)
-> log `landed <branch> -> <base> [pr <url>]`; status shows `landed` until
the next round. The base *ref* is new state: `Binding.Base` today is the
commit the branch was cut at (`types.go:369-374`), so `add`/`fork` also
record `BaseRef` (the planner's branch name at the time, `""` when
detached) and `land` requires `--onto` when it is empty. Design question
1: rebase, with `--merge` as the escape hatch (`git merge origin/<base>`,
no rewrite). Question 2: no `--squash`. Question 3: the verb is the
mechanical version; a round can still do it.

```
// internal/store/types.go  Binding
BaseRef  string    `json:"base_ref,omitempty"`   // the branch name add/fork cut from (e.g. "main"); "" for older bindings, detached HEAD, --cwd, --branch adoptions (use the upstream if you like: NO -- keep "" and require --onto; simpler)

// internal/relay/land.go
type LandOptions struct {
    Onto   string // base ref override; required when Binding.BaseRef == ""
    PR     bool
    NoGate bool
    Force  bool   // land with an open round
    Merge  bool   // merge origin/<base> instead of rebasing
    Exec   func(ctx context.Context, dir string, logPath string, argv ...string) (exitCode int, out string, err error)   // nil = real os/exec; tests stub it (gate command and gh)
    LookPath func(file string) (string, error)  // nil = exec.LookPath
}
type LandResult struct {
    Branch, Base string
    Rebased      bool     // false when --merge
    GateResult   string   // "pass" | "skipped" | "none"
    Pushed       bool
    PRURL        string   // when created
    PRCommand    string   // printed when not created
}
var ErrLandDirty = errors.New("worktree has uncommitted changes; commit first, or send a round that commits")
var ErrLandConflict = errors.New("rebase conflicts")   // wrapped with the paths
var ErrLandGate = errors.New("gate failed")
var ErrLandRoundOpen = errors.New("round is open; wait for it or pass --force")
// exit codes: ErrLandDirty / ErrLandGate -> 2; ErrLandConflict -> 3; everything else 1
```

## 6. Error handling

- Nothing is pushed until the gate passed; a conflict leaves the worktree
  as it was (`--abort` ran).
- A `gh` failure after the push is reported as such with the push already
  done; the printed command lets the human retry.
- Real `Exec` default: `exec.CommandContext(ctx, argv...)` with `Dir`,
  combined output captured to `out` and, when `logPath != ""`, also written
  there.
