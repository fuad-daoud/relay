## 1. System overview

Every save of `bind.json` or a planner record rewrites the whole file from the Go struct. So a relay binary older than the one that last wrote the file silently erases fields it doesn't know. This happens routinely now: a planner session's `relay mcp` outlives upgrades, and a rollback runs an older binary.

This round gives both records a **format number**. The rules:
- format 1 is today's shape and is stored as an absent field, so existing files stay byte-identical;
- a binary refuses to overwrite a newer format and says why;
- the daemon skips a newer-format binding instead of reconciling it;
- an unknown `State` is left alone.

A golden-shape test makes it impossible to add a JSON field to either struct without bumping the format.

## 4. Interfaces and contracts

- `func Keys(t reflect.Type) []string`: the rules are in spec §3. The tests cover a struct with a tagless field, a `-` field, an `omitempty` option, an embedded struct, a pointer, a slice of structs, a map of structs, a `time.Time`, and a type with a `MarshalJSON` method (a leaf).
- `func storedFormat(n int) int`: 0 when `n == 1`, otherwise `n`. It is unexported, one helper per package, or exported from store and reused by planner; pick one and say which.
- `func KnownState(s State) bool`: true for exactly the constants in types.go:13-24 (active, needs_you, broken, done, paused). The legacy states are already mapped on load.
- The Warn-once memory in `tickOne` and `Reconcile` is a package-level `sync.Map` keyed by binding name plus the reason. That is acceptable, since it is only a log dedupe.

## 5. High-level pseudocode

```
store.save(b):
  if b.Format > BindingFormat: return &ErrNewerFormat{Kind:"binding", Name:b.Name, Have:b.Format, Know:BindingFormat}
  b.Format = storedFormat(BindingFormat)
  ... unchanged ...

tickOne: loaded := tx.Load(name) ...
  if loaded.Format > store.BindingFormat { warnOnce(...); return nil }

Reconcile dispatch, first thing:
  if !store.KnownState(b.State) { warnOnce(...); return b, nil }
```

## 6. Error handling strategy

- `ErrNewerFormat` propagates as the command's error. Its text is spec §3's, exactly.
- Nothing is written on refusal, not even a temp file: check before `writeFileAtomic`.
- The daemon logs a Warn and doesn't halt.
