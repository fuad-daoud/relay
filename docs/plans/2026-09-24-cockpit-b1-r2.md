# Cockpit B1, round 2: the shell, the three views, the deletions, the test port

This is the round-2 send of `docs/plans/2026-09-24-cockpit-b1-shell.md`, which is
reproduced in full below this section. Its §1–§8 are the design this round implements.
**This section replaces that plan's "Round 2" outline and moves its step 3.3 (goldens)
into this round**: round 2 changes every screen, so the old goldens cannot pass. Round
3 keeps only 3.1, 3.2, 3.4 and 3.5.

Round 1 is on this branch as commit `afd913e` ("lift the detail pane out of Model into
roundPane"). Line numbers below are **after** that commit.

**If a step is impossible as written or contradicts what you find, stop and report. Do
not improvise.** The deletion list (plan §3, X1–X7) is closed. Every test you delete
must cite an X item in the report, and every test of a surviving behaviour (plan §3,
"Surviving behaviour") must end up ported.

CI has no harness and no network. Nothing here spawns a harness. The only `cmd/relevo`
edits are two lines in `cmdUI` (step R2.9), and no `cmd/relevo` test runs `relevo ui`.

**R2.4 `view_round.go`.**
- Deliverable: plan §4.5 and §5.4 (roundView).
- `newRoundView(env Env, key string, round int) (View, tea.Cmd)` builds a
  `roundPane` from `env` (`src`, `ctx`, `now`, `report`, `width = env.Width`,
  `rows` = the body height below), then calls `pane.pointDetailAt(key)`. That call
  also runs `MarkViewed`. When `round > 0`, it then sets `pane.detail.round = round`
  and clears the caches and scroll the way `stepRound` does, and returns the fetch.
- `newHistRoundView(env, h, round)` does the same through `pointDetailAtHist`.
- Body height: `bodyHeight(env)` is a package func in `frame.go` (R2.7) that
  computes plan §5.3's formula from `env.Height` and the shell's error rows. Pass the
  error rows through `Env` as a new field `ErrRows int`, set by the shell.
- Verify: `go build ./internal/ui/`.

**R2.6 `cmdline.go`.**

## Working efficiently

A builder pays one round trip per step whatever the step does, so:

- Batch the reads: the files named above, read once each.
- Write each new file in one call.
- R2.8's deletions can be one `git rm` plus the few edits.
- R2.10 is the long step. Do it file by file, each file's edits in one call, then
  `go test ./internal/ui/...` once per file.
- Run `make check` once at the end.
