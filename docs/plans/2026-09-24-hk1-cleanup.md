## 1. System overview

The relevo CLI (`cmd/relevo`) still carries leftovers from removed features:
- a `relevo answer` hint (the verb was removed in #303);
- a `relevo watch` hint (the verb never existed);
- a `--headless` flag that bind/add/fork/ask accept and ignore;
- a no-op `gc --archive`;
- an "answer" tool named in the plugin marketplace description.

It also has three bugs:
- 19 handlers parse flags with raw `fs.Parse`, which stops at the first positional, so a flag
  after a positional is silently dropped (the #48 bug class; `parseFlags` at
  `cmd/relevo/main.go:215-256` already fixes it for every other verb);
- the opencode deliverer looks for opencode's `service.json` under `$XDG_STATE_HOME`, but
  opencode writes it under the config dir;
- `.gitignore` does not cover a stray `/relay` binary.

## 4. Contracts

- **`parseFlags(fs, args) error`** (unchanged, `cmd/relevo/main.go:230`). It returns `errHelpShown`
  for `-h`, otherwise the flag error. The converted handlers currently map any parse error to
  `exitCodeErr{code: 2}`. **Keep that mapping for real errors, but let `errHelpShown` through
  unchanged**, so `-h` exits 0 the way every other verb does:
  `if err := parseFlags(fs, args); err != nil { if errors.Is(err, errHelpShown) { return err }; return exitCodeErr{code: 2} }`.
  Where a handler returns the error in some other way, keep that behaviour and let only
  `errHelpShown` through.
- **`opencodeServiceFile() string`** (renamed from `opencodeStateFile`, `cmd/relevo/main.go:475-484`).
  It returns `$XDG_CONFIG_HOME/opencode/service.json` when `XDG_CONFIG_HOME` is set, else
  `~/.config/opencode/service.json`. Evidence: on this machine, opencode v2.0.14 with
  `XDG_STATE_HOME` set wrote `~/.config/opencode/service.json`, and there is none under
  `~/.local/state/opencode/`. The doctor already reads the config path
  (`internal/doctor/opencode.go:15`); leave the doctor as it is. The `OpencodeDeliverer.StateFile`
  field keeps its name (its tests set it); only its comment changes.

## 7. Working efficiently

- Batch independent reads and edits as parallel tool calls in one step. Every location below is
  given; don't search for them again.
- Make every change to a file in one edit call. Steps 1 and 3 are mechanical: use one scripted
  edit (e.g. `sed -i` over the listed line numbers, or a short Go/perl script), then read the
  diff once.
- Focused loop: `go test ./cmd/relevo/ ./internal/relevo/ ./internal/ui/ ./internal/candidate/`.
  Fix every failure before the next run.
- Full check once, at the end: `make check` (gofmt over tracked files, go vet, go mod tidy check,
  tests).
- CI has no harness binary and no network: no new test may run a subcommand that spawns a harness
  or reaches the network. Step 1's test runs `serve available` against an **uninitialised temp state
  dir**, which fails before any network or harness use. The package's TestMain already points
  HOME/XDG_* at a temp root.
