## 1. System overview

Part 1 (#222) runs the binding's gate command after the marker
(`internal/relay/gate.go` `gateStep`; `reconcile.go:466` `closeOnMarker`
decides `pass|fail|timeout|error`, annotates the report entry with
`GateRecord` and `gate=<result>`, and closes the round: `Round++`,
`RoundStartedAt` zero, `GateRun nil`, `reconcile.go:801-830`). A failing
gate is reported, never acted on. Part 2 adds the bounded, opt-in repair:
when the round closes with `gate=fail` and the binding has `Regate > 0`,
relay -- in the same tick, after the report is queued to the planner --
stages a repair plan as round N+1's plan file, hands it to the builder the
way `Send` does (headless: `startRound`; pane: `promptWithRetry`), logs
`repair k/M`, and counts it. Two bounds end the loop with `NEEDS YOU`
instead of another repair: `RepairCount == Regate`, and a gate output
whose normalised signature equals the previous failure's (the builder
changed nothing that mattered). A human `send` or a `pass` resets the
count. The original round is closed exactly as today (its report, diff and
`gate=fail` stand); `NNN-done` is never written or removed by relay. The
server runs the same reconcile, so a remote headless binding gets it too.
Design question 2 from the issue is answered "yes, headless included" --
that is the case the repair is for; question 3 (gate outliving the round
budget) is unchanged and out of scope.

## 5. Pseudocode

Covered by §4. Tick order at a failed-gate close: `closeOnMarker` closes ->
`deliverAndSettle` queues/prompts the report to the planner ->
`startRepairRound` stages and hands round N+1 (or halts). All under the
same store lock, saved once by the daemon as today.

## 6. Error handling

- Every failure inside `startRepairRound` after the round closed becomes a
  `haltBinding` with a reason naming the repair; the closed round's report
  is already queued, nothing is lost.
- `gateSignature` unreadable -> `""` -> the signature bound is skipped (the
  count bound still holds).
- `--regate` on a binding with no gate is accepted and inert (`Gate == ""`
  never produces `fail`); `bind`/`add` print `regate N (no gate configured)`
  in that case.
