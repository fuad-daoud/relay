# Cockpit A1, round 3: three fixes to round 2

Rounds 1 and 2 are on this branch (`1c4e002` and the round-2 commit). Round 2 was
verified. These are corrections where the plan's wording was ambiguous. **Do only these
three fixes.** The A1 plan and the spec are appended for context.

**If a fix is impossible as written or contradicts the code, stop and report. Do not
improvise.** CI rules are unchanged: pure tests only, and nothing spawns a harness.

## F1. No escape sequences in the candidates block

- **Now:** round 2 renders the token column through `faint()`
  (`internal/relevo/candidates_list.go:89-92` and 114-127), which writes
  `\x1b[38;5;245m`. `relevo config` is read by planners through a pipe, so those bytes
  reach them as noise. The plan's "in faint text" meant a quieter column, not an SGR
  sequence.
- **Change:**
  - Delete `faint()`.
  - Print the padded token plainly in its own column, after the name, separated by
    two spaces, as the other columns are.
  - Remove the `testFaint` literals from `candidates_list_test.go` and
    `roles_views_test.go`. They now expect plain text.
- **Test:** add `TestFormatCandidatesHasNoEscapes`. The output of
  `FormatCandidatesLatencyFor` over a fixture must not contain `"\x1b"`.

## F2. The probe column is sized from names

- **Now:** `cmdCandidates` (`cmd/relevo/main.go:860+`) sizes the probe column from
  tokens, but `FormatProbe` prints names.
- **Change:** size it from the names `FormatProbe` will print. That is
  `rt.Candidates.NameOf(token)` of each resolved argument. The width function must be
  the same one `FormatProbe` uses, or read `ProbeResult.Name`.
- **Test:** only if a pure seam exists. If the width logic sits inline in
  `cmdCandidates`, move it into a small pure helper, `probeNameWidth(names []string)
  int`, beside `FormatProbe` in `internal/relevo/probe.go` and test it. Do not drive
  `config --probe` in a `cmd/relevo` test, because that spawns harnesses.

## F3. A name field is set only when there is a name

- **Now:** `BuilderName` (`status.go:335`), `Gate.Name` (`ledger.go:280`) and
  `DryRun.CandidateName` (`send.go:562`) are filled with `NameOf`, which returns the
  token for a candidate that is no longer configured. JSON then carries
  `"builder_name"` equal to the token.
- **Change:**
  - Add `func (s *Set) NameFor(token string) (name string, ok bool)` in
    `internal/candidate/candidate.go`. `ok` is true only when the set holds the token;
    a nil set gives `"", false`.
  - The three fields use `NameFor` and stay empty when `!ok`.
  - The renderers already fall back to the token when the field is empty. Confirm that
    for `RenderStatus`'s builder line, `writeGatedBlock`, `serve.RenderGates` and
    `dryRunBuilderLine`.
  - `NameOf` is unchanged.
- **Tests:**
  - `TestNameFor`: known, unknown, nil set.
  - Extend `TestStatusJSONHasBuilderName` with a binding on a retired token. That
    binding's JSON has no `builder_name` key, and its text line prints the token.
