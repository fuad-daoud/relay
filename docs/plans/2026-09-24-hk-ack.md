# HK-ACK: an owner's ack settles the served log, so DONE server bindings stop showing a pending report

**Stop rule:** if a step is impossible as written or contradicts the code, stop and report. Do not
improvise and do not bend a test to fit.

## 1. System overview

On a `relevo serve` host, a served binding's round report is a `to_planner` log entry that the
server never delivers itself. `deliverAndSettle` returns early for owned bindings
(`internal/relevo/reconcile.go:586-590`); the owner fetches the report over the wire and acks.

The ack handler `handleAckRound` (`internal/serve/rounds.go:491-530`) records the ack only in
`bind.json` (`b.Serve.AckedRound`, lines 517-519). It never confirms the log entry. `relevo serve
status` computes "pending" from the log (`internal/relevo/status.go:515-521` → `Store.PendingForPlanner`,
`internal/store/log.go:422-435`, the first `DirToPlanner && !Confirmed` entry). So every acked round
shows `pending report round N -> planner` forever. On contabo that is 61 of 63 DONE bindings.
`handleDone` (`internal/serve/bindings.go:259-306`) doesn't settle the log either.

The fix: acking round n confirms every unconfirmed `to_planner` entry with `Round <= n`, using
route `"ack"`. Done confirms every one with `Round <= ClosedRound`. The server daemon settles
existing data once when it starts.

## 4. Contracts

**`func settleServed(tx *store.Tx, name string, upTo int) (int, error)`** in `internal/serve/ack.go`.
- **Pre:** the caller holds the store lock (it is inside `rt.Store.WithLock`).
- **Behaviour:** read the log with `tx.ReadLog(name)`. For each index i whose entry has
  `Direction == store.DirToPlanner && !Confirmed && Round <= upTo`, call
  `tx.ConfirmIndex(name, i, "ack")`. Indices are stable because nothing appends while the lock is
  held, and ConfirmIndex rewrites a line in place without changing the count.
- **Returns** how many entries it confirmed. `upTo <= 0` is a no-op that returns 0.
- **Errors:** those of ReadLog and ConfirmIndex, wrapped as `settle %s: %w`.

**`func (s *Server) settleAllServed() error`** in `ack.go`.
- **Pre:** the caller holds `s.mu`, or no request is being served yet.
- **Behaviour:** list owner dirs exactly as `Tick` does (`internal/serve/daemon.go:20-35`,
  `remote.IDFromDir`). For each owner, build a runtime with `s.runtimeAt(ownerPath)`. In one
  `rt.Store.WithLock`, for each binding in `tx.List()` with `Serve != nil`:
  - `upTo = Serve.AckedRound`;
  - if `State == store.StateDone`, `upTo = max(upTo, Serve.ClosedRound)`;
  - then `settleServed(tx, b.Name, upTo)`.
- **Logging:** one `slog.Info("settled served reports", "owner", id, "entries", n)` per owner
  with n > 0. A per-owner error is logged at Warn and the loop continues. It returns nil unless
  the bindings dir cannot be read (a missing dir returns nil, as Tick does).

## 5. Pseudocode

```
handleAckRound (rounds.go:516-525), replacing the bare AckedRound bump + rt.Store.Save(b):
  rt.Store.WithLock(tx =>
     b2 = tx.Load(name)                         // re-read under the lock
     if b2.Serve != nil and n > b2.Serve.AckedRound: b2.Serve.AckedRound = n
     tx.Save(b2)
     settleServed(tx, name, n))
  on error -> the same 500 writeErr as today's Save failure
  (the existing reload + ReadLog + ServedView response stays unchanged)

handleDone (bindings.go), after relevo.Done succeeds and before the reload:
  rt.Store.WithLock(tx =>
     b2 = tx.Load(name)
     if b2.Serve != nil: settleServed(tx, name, b2.Serve.ClosedRound))
  on error -> slog.Warn and continue (done already happened; the response is unchanged)

Server.Run (daemon.go:64): before the ticker loop starts:
  s.mu.Lock(); if err := s.settleAllServed(); err != nil { slog.Warn(...) }; s.mu.Unlock()
```

The `n > b.Serve.ClosedRound` validation above the change (rounds.go:512-515) stays exactly as it is.

## 6. Error handling

These are server-internal, with no new wire codes. The ack keeps today's 500 on a storage error.
done and startup log a failure and never fail the request or the daemon over it.
