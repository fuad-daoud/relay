Standalone follow-up to the commit already on this branch
(`feat(serve): relay serve ui -- the fleet view on the server, grouped by client`).
`main` moved under it: #247 (`feat(persistence): relay.db as the system of
record ...`) reworked the same `internal/ui` fetchers. `git rebase origin/main`
conflicts in `internal/ui/{detail,fetch,fetch_test,keys,model,ui}.go`. This
round resolves that rebase so **both** designs survive intact.

If any step is impossible as written or contradicts the code, **halt and

`railRows()` = live rows ∪ "hist" rows (`railRow{live *BindingStatus, hist *...}`),
`pointAtRow`, `pointDetailAtHist`, `resolveStickyRows`; `fetchShow(ctx, rt, name, round, section)`

## 2. The one contract addition

```
type Source interface {
    Status(ctx) (relay.Report, error)
    Runtime(key string) (rt relay.Runtime, name string, ok bool)
    // Base is the runtime for fleet-wide reads that are not per row: the
    // database behind scope all and a hist row's tabs. On a planner it is
    // the planner's own runtime. On the server it carries no DB, so scope
    // all is refused there with the existing "no database" notice.
    Base() relay.Runtime
}
```

- `plannerSource.Base()` returns `rt`.
- `serverSource.Base()` returns `relay.Runtime{Now: time.Now}` -- `DB` nil,
  nothing else needed by the callers below. If a caller needs more from
  `Base()` on the server, halt and report which.
