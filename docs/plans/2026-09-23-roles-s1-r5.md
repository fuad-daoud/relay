## 1. System overview

- **`roles.FromLegacy`** translates today's `candidates.json` `roles`/`tier`
  and `policy.json` `order`/`tier` into a `roles.File`. For every ordered
  role, the file it produces makes the registry pick exactly what the legacy
  registry picks.
- **`relay roles init`** writes that file, and `relay roles` prints the
  registry.
- **Both commands are thin.** All their logic is in pure functions in
  `internal/roles` and `internal/relay`, tested there.

## 3. Data structures and interfaces

### 3.1 `internal/roles/init.go`

- `var ErrAmbiguousTier = errors.New("candidates of one role carry different tiers")`

- **`func FromLegacy(set *candidate.Set, pol policy.Policy) (*File, []string, error)`**
  - The second return is the notes: human lines for the CLI to print.
  - Build `reg := Build(nil, set, pol)`, the legacy registry. For each name
    in `harness.RoleNames()` (built-ins only), write one `Row`:
    - **`Candidates`:** the `Token` of every entry in `reg.Role(name).Ranked`,
      in order: ordered first, then unlisted. The field is always non-nil,
      so write `[]string{}` when there are none. An `order` token that
      doesn't serve the role is dropped. It was skipped at resolution
      anyway.
    - **`Tier`**, first match wins:
      1. `pol.Tier[name]`, if set;
      2. the candidates' own tiers, if every candidate in `Candidates` has
         the same non-empty `Tier`: use that;
      3. no candidate in `Candidates` has a `Tier` set: leave `Tier` nil;
      4. otherwise, when the tiers differ or only some are set: return
         `nil, nil, fmt.Errorf("%s: %s: %w", name, <token=tier pairs, sorted, empty shown as "none">, ErrAmbiguousTier)`.
    - **`Shape`, `Gate`, `Definitions`:** nil. Legacy has no custom
      definitions, and the built-in shape is implied.
  - **Notes, in `harness.RoleNames()` order:**
    - When `!reg.Role(name).Ordered` and `len(Candidates) > 1`:
      `<name>: <n> candidates had no order (relay refused to choose); written in ref order -- reorder roles.json <name>.candidates`.
    - When the role has unlisted entries after ordered ones:
      `<name>: <k> candidate(s) not in order.<name> appended after it, as relay ranked them`.
  - **Postcondition:** for each role with `Ordered == true` in the legacy
    registry, `Build(result, set, pol).Role(name).Ranked` tokens equal the
    legacy `Ranked` tokens.

- **`func (f *File) Encode() ([]byte, error)`**
  - JSON, 2-space indent, and a trailing newline.
  - Rows are keyed by role name. encoding/json's sorted map-key order is fine.
  - Each row emits only its non-nil fields, using the JSON names round 1
    defined. Empty `candidates` is emitted as `[]`.
  - Round-trip: `LoadWithWarnings` of the encoded bytes yields no warnings,
    and a `File` whose rows deep-equal the input.

### 3.2 `internal/relay/roles_list.go`

**`func FormatRoles(reg *roles.Registry) string`**
- Pure. One block per role in `reg.Names()` order, with a blank line between
  blocks:

  ```
  <name>  <writer|reader>[  gate]  tier <tier or ->  (<reg.Source()>)
    candidates  <tok>, <tok>      or   candidates  (none)
    <kind>  <agent>[ + <req> ...][  (custom)]
  ```

- The first line: `writer` for `harness.ShapeBuilder`, `reader` otherwise.
  `  gate` only when `Role.Gate`.
- The tier comes from the stored role tier. It can't be read through
  `TierFor`, which needs a candidate. **If the registry exposes no way to
  read a role's own tier without a candidate, add one:**
  `func (r *Registry) RoleTier(name string) (harness.Tier, bool)`. It returns
  the file tier in file mode, and `pol.TierFor(name)` in legacy mode. Put it
  in `internal/roles/registry.go`, list that file in your report, and test
  it in `init_test.go`. This is the one allowed file beyond §2.
- Kind lines: one per kind in `Role.Definitions`, sorted. `<req>` items are
  joined with ` + `, e.g. `plan-executor + researcher`. `  (custom)` is
  appended when `Definition.Custom` is set.

### 3.3 `internal/relay/candidates_list.go`: merged gate texts

Where both forms build the `unavailable:` parts from a row's gates:
- Group the gates by `(GateKindText(g.Kind), GateUntilText(g.Until))`, in
  first-seen order.
- A group whose gates all have `Role == ""` renders exactly as today:
  `<kind text> <until text>`.
- A group with any `Role != ""` renders as
  `<kind text> (<roles, sorted, de-duplicated, joined ", ">) <until text>`,
  e.g. `roles missing (builder, reviewer) until cleared`.
- Groups are joined with `"; "` as today.

Existing tests have no role-scoped gates in listings, so their output is
unchanged. If one fails, **stop and report**.

## 4. Error handling

- `ErrAmbiguousTier` stops `roles init` before anything is written.
- An existing `roles.json` without `--force` is refused before writing.
- A write failure removes the `.tmp` file (best effort) and returns the
  error.
- `relay roles` never fails on registry content. It lists what is there.
