## 1. System overview

`relay ui` is welded to one `relay.Runtime`. It uses it for five things:
`relay.Status`, `Store.Load`, `Store.ReadLog`, `Store.BuilderLogPath`, and
the herdr terminal read (pane builders only). This round puts those behind a
two-method `Source` interface with two implementations: `plannerSource`
(one runtime -- today's behaviour, no branch) and `serverSource` (every
enrolled client's store on a serve box, via `serve.AdminStatus`). Rows gain
`Owner`/`OwnerLabel` (empty on a planner), a composite `Key()` so two
clients' `persist` bindings never collide, and owner-first sorting so a
client's cards stay contiguous under a header in the rail. A new verb
`relay serve ui` builds the server source through `adminRoot` and
`serveAdminConfig` (both already in `cmd/relay/serve.go`).

## 3. Data structures

### 3.1 `relay.BindingStatus` -- two fields

| field | type | JSON | planner | server |
|---|---|---|---|---|
| `Owner` | `string` | `owner,omitempty` | `""` | `string(remote.ClientID)` -- the `SHA256:<base64>` fingerprint |
| `OwnerLabel` | `string` | `owner_label,omitempty` | `""` | `Clients.LabelOf(id)`; when that is `""`, `shortOwner(Owner)` |

Doc comment on both: empty means a planner row; renderers key new behaviour
on `OwnerLabel != ""` only.

### 3.2 `func (b BindingStatus) Key() string`

`Name` when `Owner == ""`; otherwise `Owner + "/" + Name`. Doc: the UI's
row identity; two clients may share a binding name.

### 3.3 `func shortOwner(id string) string` (package `relay`, unexported, in `status.go`)

`SHA256:` + first 12 characters after the prefix + `…` when the id has the
prefix and is longer than 19 runes; otherwise the id unchanged. Exported as
`ShortOwner` **only if** `ui` needs it (it does: §5.1 header) -- so export
it: `func ShortOwner(id string) string`.

### 3.4 `ui.Source`

```
type Source interface {
    // Status is one refresh: the whole fleet this UI shows.
    Status(ctx context.Context) (relay.Report, error)
    // Runtime resolves a row key to the runtime that owns it and the bare
    // binding name inside that runtime's store. ok is false when the key
    // cannot be resolved (server: malformed key or unknown owner); a
    // planner source resolves every key.
    Runtime(key string) (rt relay.Runtime, name string, ok bool)
}
```

- `type plannerSource struct{ rt relay.Runtime }` -- `Status` = `relay.Status(ctx, rt)`; `Runtime(key)` = `(rt, key, true)`.
- `type serverSource struct{ srv *serve.Server }` -- exported constructor
  `func ServerSource(srv *serve.Server) Source`. `Status` = `serve.FlatStatus(ctx, srv)`.
  `Runtime(key)`: `i := strings.IndexByte(key, '/')`; `i <= 0` or `i == len(key)-1`
  -> `ok=false`; `rt, err := srv.OwnerRuntime(remote.ClientID(key[:i]))`;
  `err != nil` -> `ok=false`; else `(rt, key[i+1:], true)`.

## 4. Interfaces

### 4.1 `relay.SortRows(rows, attention)` -- contract change

Primary key `OwnerLabel` ascending (plain `<`), stable; then exactly today's
comparison. Postcondition pinned by test: for input with every label `""`,
output is identical to today's.

### 4.2 `func FlatStatus(ctx context.Context, s *Server) (relay.Report, error)` (`internal/serve/admin.go`)

- Calls `AdminStatus(ctx, s)`; error propagates unchanged.
- For each `OwnerStatus o` (already label-sorted), for each row: `Owner = string(o.Owner)`;
  `OwnerLabel = o.Label`, or `relay.ShortOwner(string(o.Owner))` when `o.Label == ""`;
  append to `out.Bindings`.
- `out.Gated` = the first owner's `Report.Gated` (server-wide ledger; every
  owner's slice is the same); `nil` when there are no owners.
- `DoneHidden` 0, `HerdrError` `""`.
- Precondition: none beyond `s != nil`. Postcondition: `len(out.Bindings)` =
  sum of owners' rows; order = owners by label, rows in each owner's
  `Report` order.

### 4.3 `func (s *Server) OwnerRuntime(id remote.ClientID) (relay.Runtime, error)` (`internal/serve/serve.go`)

Exactly `s.runtime(id)`, exported. Keep `runtime` and have it call
`OwnerRuntime` (or the reverse) -- one body.

### 4.4 `ui.RunSource(ctx, src Source, opts Options) error` (`internal/ui/source.go`)

Body is today's `Run` minus the `rt.Herdr == nil || rt.Store == nil` check,
which moves into `Run` (planner only). The tty refusal message is
parameterised: `Options.PipeHint string` -- `""` means today's text
(`relay ui needs a terminal; use `relay status` or `relay watch` when piping`);
`cmdServeUI` passes `relay serve ui needs a terminal; use relay serve status when piping`.
Doc on `Options.PipeHint`: the full refusal line, not a suffix.

`Run(ctx, rt, opts)` = the nil check, then `RunSource(ctx, plannerSource{rt}, opts)`.
Its doc comment and contract are unchanged.

### 4.5 `newModel(ctx, src Source, opts)` and the fetchers

- `Model.rt relay.Runtime` becomes `Model.src Source`.
- `fetchStatus(ctx, src)`, `fetchReport(ctx, src, key)`, `fetchTerminal(ctx, src, key, lines)`,
  `fetchDiff(ctx, src, key, round)`, `fetchLog(ctx, src, key)`, `fetchFor(ctx, src, t, key, round, lines)`.
  Each fetcher that needs a runtime begins:
  `rt, name, ok := src.Runtime(key); if !ok { return <that tab's existing "gone" tabMsg with name: key> }`
  and uses `name` where it used the old `name` for store paths, `key` in the
  `tabMsg.name` it returns. Look at each fetcher's current empty-state
  text for a gone binding and reuse it verbatim.
- `tabMsg.name` is documented as "row key (BindingStatus.Key())".

### 4.6 Key-based identity in the model

Every comparison listed here switches from `Name` to `Key()`:
`row()` (`model.go:103`), `keys.go:99` (`sticky = rows[c].Key()`),
`list.go:44` and `:57`, `model.go:297` (`m.detail.name != m.rows()[cursor].Key()`),
`model.go:457` (`b.Key() != m.detail.name`), `pointDetailAt(key)` callers pass
`Key()`. `detail.name` keeps its field name; its comment becomes "row key".
`m.notice` at `model.go:198` shows `Key()` (it already receives
`m.detail.name`).

### 4.7 `railLines` (`internal/ui/rail.go`)

Signature unchanged. New behaviour: partition `rows` into maximal runs of
equal `OwnerLabel` in slice order (rows are owner-sorted by §4.1). If there
is exactly one run and its label is `""`: today's body, unchanged. Otherwise
for each run `[lo, hi)`:

1. header: `fit(" " + label + "  (" + faintStyle.Render(relay.ShortOwner(rows[lo].Owner)) + ")  " + faintStyle.Render(strconv.Itoa(hi-lo)), width)`, `binding: -1`;
2. the run's cards through today's logic (including the per-state
   sub-headers when `attention`), **with `binding` = global row index**
   (refactor the body into a helper taking `[lo, hi)`);
3. `fit("", width)`, `binding: -1`.

### 4.8 `paneHead` (`internal/ui/pane.go`)

When `b.OwnerLabel != ""` the `planner` line is replaced by
`label("client") + b.OwnerLabel + "  (" + dimStyle.Render(relay.ShortOwner(b.Owner)) + ")"`.
Line count of the returned slice is unchanged.

### 4.9 `cmdServeUI(args []string) error` (`cmd/relay/serve.go`)

```
fs: "state" string, "interval" duration (default 0 -> ui default)
root <- adminRoot(fs)                       ; error -> return (before any tty check)
srv  <- serve.New(serveAdminConfig(root))   ; error -> return
ctx  <- signal.NotifyContext(Interrupt, SIGTERM)
return ui.RunSource(ctx, ui.ServerSource(srv), ui.Options{
    Interval: *interval,
    PrefsPath: filepath.Join(root, "ui.json"),
    PipeHint: "relay serve ui needs a terminal; use relay serve status when piping",
})
```

Dispatch: `case "ui": return cmdServeUI(args[1:])` next to `"status"`. Usage
gains `       relay serve ui [--state <dir>] [--interval 2s]` after the
`status` line.

## 5. Pseudocode

```
FlatStatus(ctx, s):
    owners <- AdminStatus(ctx, s)          ; error -> return
    out <- Report{}
    for o in owners:
        label <- o.Label or ShortOwner(o.Owner)
        for row in o.Report.Bindings:
            row.Owner <- o.Owner ; row.OwnerLabel <- label
            out.Bindings += row
    if len(owners) > 0: out.Gated <- owners[0].Report.Gated
    return out

railLines(rows, ...):
    runs <- split rows into runs of equal OwnerLabel
    if len(runs) == 1 and runs[0].label == "": return today's body over all rows
    for run in runs:
        emit header(run)
        emit cards(run.lo, run.hi)   ; today's logic, global indices
        emit blank
```

## 6. Error handling

Per spec §8: uninitialised root -> `adminRoot` error before the tty check;
no tty -> `PipeHint` line; `AdminStatus` failure -> refresh error, last good
snapshot kept, footer marker (existing path); unresolvable key -> tab's
"gone" text; owner dir without a client record -> label = `ShortOwner`.
No new logging.
