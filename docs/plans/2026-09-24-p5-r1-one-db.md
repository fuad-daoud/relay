# P5 round 1: relevo serve uses the one machine DB; owner-scoped stores share one handle; clients, TLS and the daemon pointer move into the DB

Spec: `docs/specs/2026-09-24-db-as-record-design.md` §7, §12. Base: this branch, which is main plus P3d (archives as records), P3a record tables keyed
by live name; P3b kv documents and `Runtime.Gates`; P3c `round_file`; config and secrets in the
machine DB via `internal/config`).

**Stop rule:** if a step is impossible as written or contradicts the code, stop and report. Do not
improvise, and do not bend a test to fit. Tests change only as §8 sanctions.

**Out of scope:**
- automatic cleanup after ack (round 2);
- nothing about the gate verbs: P4a already replaced `serve gates/available/unavailable` with

  which §4.3 covers;
- `internal/migrate` (legacy, deleted later).

## 1. System overview

Today `relevo serve` opens:
- the machine DB, for config;
- `<serveRoot>/relevo.db`, for gates (`internal/serve/serve.go:109`);
- one `<serveRoot>/bindings/<owner>/relevo.db` per owner, lazily, **on every tick**, because
  `runtimeAt` (serve.go:204), `census` (admit.go:50) and `heldCPUs` (serve.go:238) call
  `store.New(ownerPath)`, and a fresh Store opens a fresh handle **that is never closed**.

Clients live in `<serveRoot>/clients.json`, TLS in `<serveRoot>/server.{key,crt}`, and an admin
shell finds a daemon's `--state` through `<defaultServeRoot>/daemon.json` (`pointer.go`).

After this round:
- **One handle, one scope per owner.** The server opens the **machine DB**
  (`store.DefaultRoot()/relevo.db`) once, and every owner store shares that handle through a new
  owner-scoped Store. The Server keeps **one Store per owner root**, so the leak is gone.
- **Records are keyed by (owner, name)** (migration 005). The local store's owner is `""`.
- **Server-wide gates** use the same DB under the key prefix `serve.`, so they never collide with
  this machine's own planner gates (`ledger`, `availability`).
- **Clients** become kv `serve.clients`, holding the same JSON array as clients.json. **TLS**
  becomes the secrets `serve.tls.key` and `serve.tls.cert`. **The pointer** becomes kv
  `serve.daemon`. Each is imported from its file when the file is present, and the file is removed.
- **Directories stay:** bindings, worktrees, repos and tmp stay under the serve root.
  **`--state` stays**, because it chooses that root.

## 3. Data structures

- **`005_owner_scope.sql`:**
  `DROP INDEX IF EXISTS binding_record_name_uidx; CREATE UNIQUE INDEX IF NOT EXISTS binding_record_owner_name_uidx ON binding_record(owner, name) WHERE archived_at IS NULL;`
  If `DROP INDEX` breaks the dialect rules in 001's header, say so and stop.
- **kv `serve.clients`:** `[]serve.Client` JSON, the same shape as clients.json.
- **kv `serve.daemon`:** `{root, pid, listen, started_at}`, the same shape as `DaemonPointer`.
- **Secrets `serve.tls.key` and `serve.tls.cert`:** PEM bytes.

## 4. Contracts

### 4.1 `internal/db/record.go`

`RecordGet`, `RecordPut` (keyed on the `r.Owner` field), `RecordArchive`, `RecordDelete`,
`RecordSetViewed` and `RecordList` all take `owner string` and match
`owner = ? AND name = ? AND archived_at IS NULL`; `RecordList` filters on owner. Events and
round files stay keyed by record id.

### 4.2 `internal/store`

- **New:** `func NewShared(root, owner string, d *db.DB) *Store`. The store uses `d` and never
  opens or closes a handle, and every record call passes `owner`.
- **Unchanged:** `store.New(root)` keeps its lazy `<root>/relevo.db` and owner `""`.
- **Every record call** in store (the map lists them: store.go:228-974, db.go:127/146,
  log.go:310-481, seal.go:112-308) passes `s.owner`.
- **`save`** writes `Owner: s.owner` into the record's column, not `b.Owner`. `b.Owner` stays
  data inside `record_json`. So a Store never writes a row outside its own scope, and P3a's B2
  test (`TestDoneRefusesQueued`) keeps passing unchanged.
- **`dbForRead` for a shared store** returns `d`, and **`dbForWrite`** returns `d`.
- **`DB()`/`DBIfExists()`** return the shared handle.

### 4.3 The Server

- `serve.Config` gains `DB *db.DB`, the machine DB, which the **caller** opens and closes.
- `cmdServeRun` opens it via the same `openDB(store.DefaultRoot()/relevo.db)` that
  `loadServeConfig` uses. **Reuse that handle; do not open a second one.**
- The admin verbs that call `serve.New` pass the same kind of handle.
- `Server` gains `stores map[string]*store.Store`, keyed by owner root and guarded by `s.mu`
  (which every caller already holds).
- `func (s *Server) ownerStore(root string) *store.Store` returns
  `store.NewShared(root, string(ownerIDOf(root)), s.cfg.DB)`, created once. `ownerIDOf` is
  `remote.IDFromDir(filepath.Base(root))`.
- **Replace** `store.New(ownerPath)` / `store.New(root)` in `runtimeAt` (:204), `census`
  (admit.go:70) and `heldCPUs` (:238, the other-owner List) with `s.ownerStore(...)`.
- **Gates:** `s.gates` / `Runtime.Gates` becomes `db.PrefixKV{KV: s.cfg.DB, Prefix: "serve."}`,
  and `serve.New` no longer opens `<serveRoot>/relevo.db`. The same applies to `ledgerRuntime`
  (admin.go:437) and `serveTierRuntime` (cmd/relevo/serve.go:194).
- `ledgerRuntime`'s lock-only `store.New(s.cfg.Root)` stays. It is used for its flock only and
  never opens the DB.
- `func (s *Server) DB() *db.DB` returns `s.cfg.DB`. The ui prefs key `serve.ui` stays as it is.
- **Hook runs:** `cmdServeRun` builds its hooks dispatcher with the machine DB's run log (`hooks.KVLog` over `cfg.DB`, the same one `relevo daemon` uses), instead of the nil run log P3b round 2 left there. Serve's hook runs then land in kv `hooks.log` like the daemon's.

`db.PrefixKV{KV KV; Prefix string}` implements `KV` (and `KVKeys`) by prefixing every key.
The legacy-file import still takes the file path, so
`ledger.LoadKV(PrefixKV, <serveRoot>)` imports `<serveRoot>/ledger.json` into `serve.ledger`.

### 4.4 Clients (`internal/serve/clients.go`)

- `LoadClients(kv db.KV, legacyPath string) (*Clients, error)`.
- Every public method re-reads the kv row **each call**, replacing the file stamp. That keeps
  today's "an admin enroll in another process is seen live" behaviour.
- `saveLocked` → `KVPut`.
- **Import:** `<serveRoot>/clients.json` present → the kv row, then the file is removed.
- Labels stay non-unique, as today.

### 4.5 TLS (`internal/serve/tls.go`)

| function | change |
|---|---|
| `InitTLS(secrets SecretStore, hosts, now)` | writes both secrets; `ErrTLSExists` if either exists |
| `LoadTLS(secrets)` | `tls.X509KeyPair` + Leaf |
| `Fingerprint(secrets)` | reads the cert secret |

- `SecretStore` is `{SecretGet, SecretPut}` over `*db.DB`.
- **Import:** `<serveRoot>/server.key` and `.crt` present → both secrets, then both files removed.
  The import happens in `LoadTLS`/`Fingerprint`/`InitTLS` before they read.

### 4.6 The daemon pointer

- `cmdServeRun` writes kv `serve.daemon` (via the machine DB) where it wrote the pointer file, and
  deletes the key on a clean exit.
- `ResolveAdminRoot(explicitState string, d *db.DB, defaultRoot string, alive func(int) bool)`:
  - explicit `--state` → `<state>/serve`;
  - else a live `serve.daemon` pid → its root, with today's note;
  - else a stale one → default, with today's stale note;
  - else default.
- `Initialised(root, d)` is true if any of these holds: kv `serve.clients` exists, the secret
  `serve.tls.key` exists, or `<root>/bindings` exists. The legacy files also count, until they are
  imported.
- **Keep `ReadPointer(defaultRoot)` (file) and `DaemonPointer`** only for
  `internal/migrate/detect.go:105`. Delete `WritePointer` and `RemovePointer` (D1).

### 4.7 doctor

- `ServeChecks(env, d *db.DB, serveRoot string, now)` reads the cert from the secret, the clients
  from kv, and the root from `serve.daemon` (or the default).
- It **runs when the `serve.tls.key` secret exists**. This also fixes today's bug that the serve
  rows never show on contabo, where `--state` is non-default.
- `cmd/relevo/doctor.go:364-367` passes the machine DB.
