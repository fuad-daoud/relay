## 1. System overview

A fresh machine today: install, `relay doctor` (which says "none
configured" and prints a one-line example), hand-write
`~/.config/relay/candidates.json` and `policy.json` from the README, `relay
agent install`, `relay doctor` again. After this round the first run is
`install -> relay init -> relay doctor -> edit the model names`: `relay init`
finds the harness binaries on PATH (the same `LookPath` scan
`harness.Install` already does, `internal/harness/install.go:83-86`), writes
one builder candidate per harness in the README's shape with `"tier":
"yolo"`, a `policy.json` ordering them in the order found with
`max_tier: yolo` and `tier.builder: yolo`, installs the role definitions
for those harnesses (folding #166 §1), refuses to overwrite either config
file without `--force`, and prints what it wrote plus the next command.
Decisions from the issue: the README's real defaults are used as the
placeholders (they are the documented examples and pass `candidate.Load`;
a `<provider>` placeholder would fail the first `relay candidates`), the
permission comes from `tier: yolo` (the current mechanism; no
`extra_args`), and roles are installed by default (`--no-roles` skips).

## 6. Error handling

- No harness on PATH: exit 1 with the message; nothing written.
- Existing files without `--force`: exit 1, nothing written (both-or-neither).
- A role install error: printed per line (as `agent install` does), exit
  1 at the end, but the config files stay written -- they are correct.
