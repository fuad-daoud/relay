# Roles S1, round 3: the #238 gate is per role and knows custom definitions (#374)

This plan is self-contained. The spec (`docs/specs/2026-09-23-roles-and-actors-design.md`
§5) is not in this tree.

State of this branch:
- Round 1 (`f784691`) added `internal/roles` (the registry) and
  `harness.DefinitionPath` / `harness.IsShipped`.
- Round 2 (`43877fa`) made runtime paths resolve through
  `rt.RoleRegistry()`: `resolveRole`, `rankedRole`, `resolveRoleTier`, and
  launch specs via `reg.Spec(role, kind)`.

Today the #238 gate checks only the builder's **shipped** definitions, per
harness kind, and gates the candidate token **for every role**. So, after
round 2:
- a custom builder definition (`roles.json` → `my-executor` on claude) is
  launched but never checked;
- a builder file missing on claude also blocks the claude reviewer.

This round makes the gate check the **resolved** definitions of **each role**
the candidate serves, and makes a roles-missing gate apply only to its role.

If a step is impossible as written or contradicts the code, **stop and
report**. Do not improvise.

## 1. System overview

- `rolesMissingGates` (`internal/relay/ledger.go:236-275`) synthesises one
  in-memory `ledger.RolesMissing` gate per (candidate, role) whose resolved
  definitions (`reg.Spec(role, kind).Definitions`) are not all on disk.
- The gate carries its role. `resolveRole` ignores gates for other roles.
- `harness.MissingDefinitions` resolves custom names through
  `harness.DefinitionPath`. Today it silently skips them.
- `candidate.Load` stops requiring `roles`, because a `roles.json` user
  deletes them.

## 3. Data structures

`ledger.Gate` (`internal/ledger/ledger.go:221-229`) gains one field, after
`Binding`:

- `Role string`: "" means the gate applies to every role. That covers every
  gate read from the ledger file, and every gate `Gated` produces. Non-empty
  means it applies only to that role. Only `rolesMissingGates` sets it.
  In-memory only: `Gate` has no JSON tags and is never written. Confirm that
  with a grep for `json.Marshal` of a `Gate` / `[]ledger.Gate`, and **stop
  and report** if any exists.

## 4. Interface definitions

### 4.1 `internal/harness/roles.go`

`RoleChecker`:
- `Missing(kind string, definitions []string) []string`: the home-relative
  path of every name in `definitions` whose file is not readable on disk for
  `kind`. nil means all are present. It replaces `Missing(kind string)`.

`MissingDefinitions(env InstallEnv, kind string, definitions []string) []string`:
- For each name, the path is `DefinitionPath(kind, name)`: the shipped
  row's `Path` for a shipped name, the convention path otherwise. It
  replaces today's `h.Role(def)` lookup, whose `!ok → continue` silently
  skipped custom names.
- An unknown kind still returns nil.
- The unreadable-path logic (`env.HomePath`, `env.ReadFile`) is unchanged.

`osRoleChecker.Missing(kind, definitions)`: `MissingDefinitions(c.env, kind, definitions)`.
It no longer looks up the builder itself. Update its doc comment and the
`RoleChecker` doc comment. They now say "the given definitions", not "the
builder role's shipped definitions".

### 4.2 `internal/relay/ledger.go` `rolesMissingGates(rt)`

```
if rt.Roles == nil || rt.Candidates == nil: return nil          (unchanged guard)
reg := rt.RoleRegistry()
cache := map[kind + "\x00" + strings.Join(defs, ",")] []string  // one disk check per distinct (kind, definition list)
for ref in rt.Candidates.Refs():                                  (sorted, as today)
  r := ParseRef(ref); kind := r.Harness
  for role in reg.Names():
    if !reg.Serves(role, r): continue
    spec, err := reg.Spec(role, kind); if err: continue
    paths := cached rt.Roles.Missing(kind, spec.Definitions)
    if len(paths) == 0: continue
    out += ledger.Gate{Token: ref, Kind: ledger.RolesMissing, Role: role, Since: rt.Now(),
                       Note: rolesMissingNote(role, kind, spec.Definitions, paths), Source: "relay"}
```

`rolesMissingNote(role, kind string, defs, paths []string) string`, pure and
unexported:
- `roles missing for <role>: <paths joined ", ">; <fix>`
- `<fix>` depends on which missing paths belong to shipped names
  (`harness.IsShipped(kind, name)` for the name whose `DefinitionPath` is that
  path):
  - all shipped: `run relay agent install --kind <kind>`
  - all custom: `install <custom paths joined ", "> yourself; relay never installs a custom definition`
  - mixed: both, joined by `; `.

Update the function's doc comment: it now covers every role a candidate
serves, and each gate carries its role.

### 4.3 `internal/relay/candidate.go` `resolveRole`

At the top of `resolveRole`, before the explicit-token branch:
`gates = gatesForRole(gates, role)`.

`func gatesForRole(gates []ledger.Gate, role string) []ledger.Gate` keeps
every gate whose `Role == ""` or `Role == role`, in order. It is pure and
returns a new slice.

Nothing else in `resolveRole` changes. The explicit-pick roles-missing
refusal loop now sees only this role's gates.

### 4.4 `internal/candidate/candidate.go` `LoadWithWarnings`

- **Delete** the `if len(c.Roles) == 0 { return ... "roles must not be
  empty" }` check (around `:215-217`). A candidate with no roles is valid.
  In legacy mode it serves nothing; in `roles.json` mode its roles are
  ignored anyway.
- **Unchanged:** the unknown-role warning-and-skip (#372), and the
  `h.CanServe(r)` check for listed roles.

### 4.5 `cmd/relay/serve.go` startup log (around `:336-352`)

`roles.Missing(r.Harness)` becomes
`roles.Missing(r.Harness, <builder definitions>)`, where the definitions are
`reg.Spec("builder", r.Harness).Definitions`. `reg` is the registry that
`loadCandidatesAndPolicy` already returns at `:332`. On a `Spec` error, skip
that kind.

## 5. Pseudocode: gate flow after this round

```
Gates(rt) = ledger gates (Role "") ++ rolesMissingGates(rt) (Role set, one per candidate×role missing files)
resolveRole(reg, set, gates, token, role):
  gates = gatesForRole(gates, role)          // a reviewer pick never sees a builder-only roles gate
  explicit token -> refused only by a roles-missing gate for THIS role
  omitted token  -> ranked walk skips gated candidates for THIS role
```

Views that list gates per token (`relay candidates`, status, doctor) are
unchanged in this round. A role-scoped gate shows there with its note, which
names the role.

## 6. Error handling

- No new errors.
- A missing definition file is never fatal. It is a gate, and the note says
  how to fix it.
- A `Spec` error in `rolesMissingGates` (the role has no definition for that
  kind) cannot happen for a candidate that `Serves` the role. It is skipped
  defensively.

## 7. Behaviour changes (all intended)

1. In legacy mode, a candidate serving reviewer or researcher is now also
   gated for that role when that role's shipped file is missing. Before, only
   the builder's files were checked.
2. A builder-only roles-missing gate no longer blocks `relay ask` or verify
   on the same candidate.
3. The note text changes from `roles missing: <paths>; run relay agent
   install --kind K` to `roles missing for <role>: <paths>; run relay agent
   install --kind K`. Existing tests assert only `Contains("roles missing")`
   and `Contains("relay agent install --kind")`, which still hold. If any
   test asserts the old exact text, **stop and report**.
