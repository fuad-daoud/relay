# P3b round 1: the kv API; ledger, availability, latency, release-check, ui prefs, agents manifest and daemon info move into relevo.db

Spec: `docs/specs/2026-09-24-db-as-record-design.md` §3.2 (`kv`), §12. Main is at `80f885c`
(P3a: the store keeps bindings in `<root>/relevo.db`; config lives in the same DB).

**Design choice for this round:** each small JSON file becomes **one `kv` row holding the same
JSON document**, rewritten whole, exactly as the file was. The semantics don't change: every
Load/Prune/Append/Save stays, and only the medium changes. The `kv` table already exists
(migration 002: `key TEXT PRIMARY KEY, value_json TEXT NOT NULL, updated_at TEXT NOT NULL`), so
**no migration is needed.**

**Import rule: a file that is present is imported.** When a store reads a key whose kv row is
absent and the old file exists, it imports the file into the row and deletes it. This migrates
existing machines.

**Stop rule:** if a step is impossible as written or contradicts the code, stop and report. Do not
improvise, and do not bend a test to fit. Tests change only as §8 sanctions.

## 3. Data structures

- The `kv` row: `value_json` is the exact JSON document the file held; `updated_at` is RFC3339Nano UTC.
- A shared minimal interface in `internal/db`:

  ```
  type KV interface {
      KVGet(key string) ([]byte, bool, error)
      KVPut(key string, value []byte) error
      KVDelete(key string) error
  }
  ```

  `*db.DB` implements it. Packages that must not import `internal/store`, such as harness (store
  → usage → harness), take a `db.KV`.

## 4. Contracts

### 4.1 `internal/db/kv.go`

- `(d *DB) KVGet(key) ([]byte, bool, error)`: a missing row returns `(nil, false, nil)`. On a
  schema without `kv` (< 2), it returns `(nil, false, nil)` via the existing `isMissingTable` helper.
- `(d *DB) KVPut(key, value)`: an upsert in one short tx. `value` must be valid JSON, else
  `ErrInvalid`.
- `(d *DB) KVDelete(key)` and `(d *DB) KVKeys(prefix string) ([]string, error)`: KVKeys is needed
  by round 2, and is sorted.
- Tx forms of the same four.

### 4.2 `internal/store/db.go`

- `func (s *Store) DB() (*db.DB, error)`: the existing `dbForWrite` (creates the DB).
- `func (s *Store) DBIfExists() (*db.DB, error)`: the existing `dbForRead` (nil when absent).
- Both are thin exports. Update the P3a comment that says "daemon-info methods never open it",
  because they now do (§4.3).

### 4.3 The import helper: one function, used by every package below

In `internal/db/kv.go`: `func KVImportFile(kv KV, key, path string) ([]byte, bool, error)`.

```
v, ok := kv.KVGet(key); if ok -> return v, true
data, err := os.ReadFile(path); missing -> return nil, false, nil
validate it is JSON (else return an error naming path)
KVPut(key, data); then os.Remove(path) (a remove error is logged, not returned)
return data, true
```

Each package's `LoadKV` calls this with its old path, then decodes exactly as today's `Load`
decoded the file bytes. **Same decode, same defaults, same "missing = empty" behaviour.**

### 4.5 Runtime and serve wiring

In `relevo.Runtime` (`internal/relevo/runtime.go:111-122`), `LedgerPath`, `AvailabilityPath` and
`LatencyPath` become:

```
Gates    db.KV   // where ledger + availability live; nil -> gates are empty, and writes are dropped with an error
GatesDir string  // legacy dir holding ledger.json / availability.json / history.json for the import
Latency  db.KV   // nil -> record nothing (as LatencyPath == "")
```

Keep each field's doc comment accurate.

**Wiring:**
- `cmd/relevo/main.go buildRuntime` sets `Gates`/`Latency` = the store root's `st.DB()` and
  `GatesDir` = the store root.
- A `DB()` error is returned from `buildRuntime`, and is fatal for the verb, as a config DB error
  already is.
- `newRuntimePeek` sets them nil. Preflight/check never touch gates.

**Serve (`internal/serve/serve.go runtimeAt` :185-205 and `admin.go ledgerRuntime` :436-446):**
- `Gates` = the **serve-root** store's `DB()`: `store.New(s.cfg.Root).DB()`, opened once in
  `serve.New` and held on the Server. This creates `<serveRoot>/relevo.db`; phase 5 merges it.
- `GatesDir` = `s.cfg.Root`.
- `cmd/relevo/serve.go serveTierRuntime` (:190) likewise.

**Locking is unchanged.** Every ledger/history write stays inside the same `Store.WithLock` it is in
today (`internal/relevo/ledger.go` :41-60, :157-201; `limit.go:360`; `headless.go:252`), and
`KVPut` is a short autocommit tx. **Never** open a `db.Tx` spanning a `WithLock` callback.

`rt.AvailabilityPath` or `rt.LatencyPath`:

## 6. Error handling

| failure | behaviour |
|---|---|
| a KVGet/KVPut error | returned wherever today's Load/Save error was returned, with the same handling at each caller (for example `appendEntryLocked` still prints a history failure to stderr and drops it) |
