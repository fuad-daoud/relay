## Why

Every existing `planner.id` in real `relay.db` files is a 26-character
Crockford-base32 ULID minted by `internal/db/ulid.go`, for example
`01M3252956S27X5G5MPVM77PJ7`. Round 1's `ValidID` accepts only
`pl_[a-z2-7]{12}`. So on every machine that has bound before, `PriorID`
returns a ULID, `Create` refuses it with `ErrInvalid`, and the hook
registers nothing. Spec §3.5 requires reusing those ids.

## Changes

1. `internal/planner/planner.go`: `ValidID(id)` accepts **either**
   `^pl_[a-z2-7]{12}$` **or** a ULID, `^[0-9A-HJKMNP-TV-Z]{26}$` (the
   alphabet `internal/db/ulid.go` uses; check it against that file and use
   the file's alphabet if it differs). `NewID` still mints only `pl_` ids.
   `Get`, file naming and `Resolve`'s id-first lookup use `ValidID`, so a
   ULID-named record `<ULID>.json` works everywhere. Both shapes are
   path-safe; keep the check that stops a ref from becoming a path.
2. `Resolve`'s "id first, else name" rule: a ULID can't be a valid name
   (names are lowercase), so there is no ambiguity. Add a table row to
   `TestResolveOrder` resolving a ULID-id record by flag.
3. `TestInitReusesPriorDBID`: change its prior id to a real ULID shape
   (`01M3252956S27X5G5MPVM77PJ7`), and keep a second case with a `pl_` id.
   Add `TestValidIDAcceptsLegacyULID`, covering both shapes and rejecting a
   lowercase ULID, 25 characters, `I`/`L`/`O`/`U`, and `pl_` plus 11
   characters.
4. **Spec §3.4's note** (your note 3). Add `HookOutputNoEnv(r Record)
   []byte`: the same envelope, whose `additionalContext` is the normal text
   followed by one space and `RELAY_PLANNER could not be exported
   ($CLAUDE_ENV_FILE is unset); relay resolves this session through its host
   process.` `relay planner init --hook claude` prints it instead of
   `HookOutput` when `CLAUDE_ENV_FILE` is empty. Add a golden test,
   `TestHookOutputNoEnvExactJSON`, and a cmd test,
   `TestPlannerInitHookWithoutEnvFileSaysSo`.
